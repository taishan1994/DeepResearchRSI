# 分阶段实现路线与验收标准

每一阶段都以**可验证的门槛**结束，而不是以"功能做完了"结束。未达门槛不进下一阶段。

## 阶段 1：可信单次研究

**目标**：一次研究任务产出的每个事实性结论都能点回来源片段。

**范围**
- `ResearchBrief` 规范化 + 子问题拆分
- 学术 / Web 检索（≥2 个 provider）
- 解析、分段、去重、内容哈希
- `Source` / `Document` / `Evidence` / `Claim` 数据模型
- 引用核验（引用存在性 + 支持关系）
- Markdown 报告 + 完整轨迹

**验收门槛**
| 项 | 门槛 |
|---|---|
| 引用闭合率 | 100%（无悬空引用） |
| 引用真实支持率 | ≥ 90%（抽样 30 条人工核对） |
| 子问题状态完备 | 100% 标注 answered/partial/unanswered |
| 报告含截止时间与范围 | 必须 |
| 轨迹可看 | 查询、来源、预算消耗可见 |

**首个真实用例**：论文进展调查（见 `research/` 下的实际任务）。

## 阶段 2：主题持续跟踪

**目标**：新信息出现时给增量变化，而不是重写整篇综述。

**范围**
- 主题订阅与调度
- 增量检索（按 `content_hash` 与版本号去重）
- 论文版本 / 引用关系
- 变化检测：新增 / 结论变化 / 待确认
- 周报视图

**验收门槛**
- 二次运行不重复生成未变化内容（去重率可测）
- 每条变化能定位到"哪次运行、哪个来源、哪个片段"
- 撤销公告（retraction）能被检出并降级相关主张

## 阶段 3：证据驱动的动态研究

**目标**：根据证据缺口花预算，而不是按固定计划烧预算。

**范围**
- 问题图（DAG）与依赖
- 覆盖度 / 缺口审计 → 定向补搜
- 跨来源冲突并列呈现
- 并行 worker 与全局预算控制

**验收门槛**
- 相同预算下问题覆盖率高于阶段 2 的固定计划基线
- 预算耗尽时返回"已完成 + 未解决"，不静默截断（不变量 R1）
- 冲突主张 100% 并列展示，不强行裁决（不变量 C3）

## 阶段 4：受控自进化

**目标**：系统能提出并验证自己的改进，但**不能**绕过门禁上线。

**范围**
- 轨迹归因（失败类型分类）
- 候选改进：检索策略 / 记忆规则 / 研究技能 / 工作流模板
- 离线评测：固定回归集 + 新任务集
- 灰度发布与一键回滚

**验收门槛**
- 候选改动必须**全项不退化**才晋级（事实正确性、引用准确率、覆盖率、时效性）
- 有配对评测与跨主题泛化检查
- 每次上线有版本号、评测报告、回滚点

**明确排除**：自动改自身代码 / 模型权重。该阶段需要人工审阅、隔离运行、版本控制和独立安全评测，不属于阶段 4 范围。

## 评测体系（贯穿各阶段）

| 层 | 指标 | 数据来源 |
|---|---|---|
| 检索 | Recall@k、来源覆盖、最新版本命中、重复率 | SearchTrace vs 参考来源集 |
| 证据 | 片段定位准确率、支持/反驳判断、元数据正确率 | Evidence 抽样人工核对 |
| 报告 | 问题覆盖、事实正确、引用准确、时效性、结构完整 | rubric 评分 |
| 系统 | 成功率、延迟、单任务成本、工具错误率 | ResearchRun.trace |
| 进化 | 配对评测、跨主题泛化、回归率、人工接受率 | evals/reports/ |

热点追踪任务必须包含**时间切片测试**，防止系统使用未来信息或把旧快照当当前事实。
