# ADR-0002：证据必须留存原文片段与抓取时间

- **状态**：已接受
- **日期**：2026-10-27

## 背景

研究报告最常见的失效模式不是"写得不好"，而是**结论无法回溯**：报告说某卡带宽 1792 GB/s，但没人知道这个数字来自哪一页、什么时候看到的、当时页面是不是这个版本。

Embedding 可以重建，摘要可以重写，但"你在什么时候看到了什么原文"不可重建。

## 选项

1. 只存来源 URL 与摘要。
2. 存来源 URL + 抓取快照 + 精确片段 + 抓取时间。
3. 存上述内容 + 完整解析管道版本号。

## 决策

选择 **选项 3**。

`Evidence` 必须包含：`quote`（原文子串，不改写）、`locator`（章节/页码）、`source_id`、`extracted_by`（抽取器版本）。
`Source` 必须包含 `fetched_at`（带时区）。
`Document` 必须包含 `content_hash` 与 `parser_version`。

## 强制不变量

- **E1**：`quote` 必须是原文子串。允许截断，不允许改写或翻译后回填。
- **S1**：`fetched_at` 必填，且必须带时区。
- **D1**：`content_hash` 变化即视为新版本，不覆盖旧记录。

这些由 `scripts/validate_research.py` 在 CI 中机器校验。

### 实现状态（2026-11-03 补记）

契约写于 2026-10-27，实现长期只有「字段非空」检查：

```python
if not quote:       报错（信息里写「不变量 E1」）
if not fetched_at:  报错（信息里写「不变量 S1」）
```

「非空」既不能证明 quote 是原文子串（E1），也不能证明时间戳带时区（S1）；
D1 则完全没有实现。错误信息里挂着不变量编号，读起来像是验过了。

现已实现在 `packages/schemas/python/deepresearchrsi/invariants.py`：

| 不变量 | 判定方式 |
|---|---|
| S1 | 正则要求 `Z` 或 `±HH:MM` 结尾，再用 `datetime.fromisoformat` 解析 |
| D1 | 同一 `document_id` 出现多个 `content_hash` 且无版本列区分即报错 |
| E1 | 读 `documents/<document_id>.txt`，quote 须为其子串（允许空白归一，不允许改写） |

**E1 的覆盖率必须单独统计。** 没有文档快照时，检查退化为「无法校验」，
此时输出 `e1_unverifiable` 并打印醒目的 `[!]` 警告，**不得记为通过**。
否则一个没有任何快照的归档会安静地显示 `[OK]`，而它几千条证据的 E1
其实一条都没验过——这比报错更危险。

`rtx-pro-6000`（3002 条证据）当前就是这种情况：`e1_checked=0`。
补快照属于 `services/ingestion` 的范围，尚未做。

## 后果

**正面**
- 任何结论都能回答"依据是原文哪一句、何时抓的"。
- 来源改版后可对比新旧快照，而不是默默用新内容覆盖旧结论。
- 解析器升级后可重放，验证抽取质量变化。

**负面**
- 存储成本高于只存摘要（快照 + 全文）。
- 抓取需要处理更多反爬与格式问题。
- 写作时必须逐句核对原文，比"凭印象总结"慢。

**接受的代价**：慢，但可审计。不可审计的报告在企业场景没有价值。
