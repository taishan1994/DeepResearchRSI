# evals/reports

一次评测运行的输出。**结果文件入库，便于跨版本对比。**

## 文件命名

```text
evals/reports/<YYYY-MM-DD>-<suite>-<git-sha>.json
evals/reports/<YYYY-MM-DD>-<suite>-<git-sha>.md      # 人读摘要
```

## 必须记录的内容

| 字段 | 为什么 |
|---|---|
| git sha | 结果必须对应确定的代码版本 |
| 策略/配置版本 | RSI 改进的对象是配置，不是代码 |
| 每个案例的分数 | 平均值会掩盖单点崩溃 |
| 失败清单与原因 | 失败的**类型**比失败率更有用 |
| 成本（token/工具调用/耗时） | 质量提升若伴随 10 倍成本则不可接受 |
| 与基线的配对比较 | 只跑新版本无法判断是否退化 |

## 配对比较优先

候选改进必须与基线在**同一批案例**上跑，报告逐案例的胜负，而不是两个独立平均值。独立平均值受案例难度波动影响，容易得出错误结论。

## 晋级判定

候选改动必须**全项不退化**：
- 事实正确性
- 引用准确率
- 问题覆盖率
- 时效性
- 可复现性

任何一项退化即拒绝，即使总分更高。
