# evals/cases

回归案例集。每个真实任务经审核后沉淀为一个案例，用于测评候选改进是否造成退化。

## 案例结构

```text
evals/cases/<case-id>/
├── case.yaml        问题、截止日期、难度、期望覆盖的子问题
├── reference.md     参考来源与关键主张（人工审核过的"正确答案"）
└── rubric.yaml      评分规则：哪些主张必须命中、哪些错误算硬伤
```

## 案例类型

| 类型 | 用途 |
|---|---|
| **事实核查** | 有唯一正确答案，考察引用准确率 |
| **对比综述** | 多方案权衡，考察覆盖度与冲突处理 |
| **时效追踪** | 考察是否使用正确时点的信息，而非未来信息 |
| **缺口识别** | 考察系统能否诚实说"没找到"而不是编造 |

## 时间切片测试

热点追踪类案例必须带时间切片：给出截止日期，检查系统**没有**使用截止日期之后的信息。这是防止"用未来信息装作预测"的关键测试。

## 案例来源

1. 真实任务（如 `research/rtx-pro-6000`）经人工审核后转化
2. 公开基准（DeepResearch Bench 等）通过 `evals/adapters/` 接入
3. 人工构造的对抗案例（诱导编造、来源冲突、撤稿追踪）
