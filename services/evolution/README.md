# services/evolution

受评测约束的自我改进（RSI 的外循环）。

## 两个循环

- **内循环（单次任务）**：研究 → 证据审计 → 找缺口 → 定向补搜 → 再审计 → 交付
- **外循环（跨任务）**：收集轨迹 → 失败归因 → 生成候选改进 → 离线评测 → 门禁 → 灰度 → 监控 → 可回滚

## 进化对象（按风险从低到高）

1. **检索策略**：查询扩展、来源选择、重排权重、停止条件
2. **研究技能**：如"追踪论文版本""横向比较实验设置""查找反证"
3. **记忆**：主题实体、用户偏好（需授权）、已见来源与结论及其有效期
4. **工作流配置**：特定任务类型的步骤与预算模板

## 晋级门槛

候选策略必须在固定回归集上**全项不退化**：

- 事实正确性
- 引用准确率
- 问题覆盖率
- 时效性
- 可复现性

同时比较检索成本、延迟与失败率。采用版本化配置、A/B 或影子评测、灰度比例与一键回滚。

## 明确排除

**本模块不修改自身代码，不修改模型权重。** 那属于更高风险阶段，需要人工审阅、隔离运行、版本控制和独立安全评测。

## 奖励信号的防偏

不只用 LLM 自评。混合：
- 可验证指标（引用是否真实存在、数字是否与原文一致）
- 人工抽检
- 用户反馈

并对评判模型自身的偏差做校验。
