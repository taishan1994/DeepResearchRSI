 Abstract

 
 Fine-grained mixed-precision quantization promises efficient large language model inference, but local precision choices can conflict with regular GPU storage and computation units.
This precision-boundary mismatch limits the translation of compression into practical acceleration.
We introduce AlignQuant , a post-training quantization method that uses GPU-compatible two-dimensional weight tiles as the common unit of precision allocation, compact storage, and execution.
This shared partition lets precision follow sensitivity within output channels.
Joint prefill/decode calibration scores precision reductions using projection-output perturbations weighted by language-model loss gradients under quantized activations.
Phase-normalized scores prioritize higher precision for tiles important to either phase under a model-wide weight-storage budget.
Each tile stores one selected representation, while phase-specialized kernels reuse the packed model and expand lower-bit weights for INT8 computation with 8-bit activations.
Across four LLMs spanning 3B to 14B parameters, AlignQuant achieves up to 2.50 × 2.50\times generation speedup over BF16 while preserving model quality.
Evaluations further cover three GPUs and contexts up to 64K tokens.
These results show that local precision flexibility and regular GPU execution can coexist through a shared tile unit.
The implementation is available at https://github.com/HanzhiZhang-Ulrica/AlignQuant .

 

 
 
 
 
 

 
 

 
 1 Introduction

 
 Large language model (LLM) inference is increasingly constrained by parameter storage, memory traffic, and computation.
Post-training quantization (PTQ) reduces these costs through lower-precision representations, while the resulting quantization error makes accuracy preservation a central challenge
 ( Dettmers et al., 2022 ; Xiao et al., 2023 ; Frantar et al., 2022 ; Lin et al., 2024b ) .
Uniform-bit quantization addresses this challenge by improving the quantized representation at a fixed weight precision
 ( Frantar et al., 2022 ; Lin et al., 2024b ) .
Mixed-precision quantization additionally exploits differences in sensitivity by assigning higher precision to sensitive weight regions under a weight-storage budget
 ( Chen et al., 2024 ; Huang et al., 2024 ; Zheng et al., 2026 ; Li et al., 2026 ; Nie et al., 2026 ; Hooper et al., 2025 ) .
However, when fine-grained precision boundaries cross regular storage or GPU computation units, the resulting precision-boundary mismatch makes efficient deployment depend on how mixed-bit weights are packed, loaded, and converted for computation
 ( Zhao et al., 2024 ; Lin et al., 2025 ) .

 
 Figure  1 illustrates how precision allocation, weight representation, and GPU execution jointly shape model quality and inference efficiency.
Existing methods manage this tension through different precision-sharing and execution structures.
Channel- and output-feature-level methods maintain regular partitions by sharing one bit-width across each channel or output feature, coupling weights with different sensitivities to the same precision choice
 ( Chen et al., 2024 ; Zheng et al., 2026 ) .
Finer-grained approaches expose more local choices through quantization groups and hardware-aligned blocks, together with reordering, mixed formats, or specialized execution support
 ( Huang et al., 2024 ; Li et al., 2026 ; Nie et al., 2026 ; Hooper et al., 2025 ) .
System-oriented quantizers co-design low-bit formats with weight layouts, dequantization, and GPU data paths to control these deployment costs
 ( Zhao et al., 2024 ; Lin et al., 2025 ) .
These approaches expose a structural trade-off: coarser sharing restricts where higher precision can be placed, while finer allocation requires coordinating the compact storage of heterogeneous weights with the formats used for GPU computation.
This leads to our central question:
 How can sensitivity-driven local precision choices be preserved in compact weight storage and direct GPU execution?

 Our key insight is to use GPU-compatible two-dimensional weight tiles as a shared unit for local precision selection, storage, and execution.
Each tile receives its own bit-width, allowing precision to vary within output channels while providing a regular unit for storing and loading the selected weights.
Our analysis supports this choice by showing that quantization sensitivity is localized within output channels.
At a matched 4-bit tile fraction, two-dimensional tile allocation improves WikiText-2 perplexity over the output-row control.
However, turning these local precision choices into efficient inference presents two coupled challenges.
First, prefill processes prompt tokens and decode generates new tokens using the same weights.
A shared precision assignment must therefore combine sensitivity evidence from both phases under one model-wide weight-storage budget.
Second, the selected mixed-bit weights must retain their compact format in GPU memory and during loading while supporting integer computation tailored to each phase’s workload
 ( Lin et al., 2025 ) .

 
 We introduce AlignQuant , a tile-aligned mixed-precision method that constructs one compact model for efficient LLM generation.
Joint loss-aware calibration assigns 4-bit or 8-bit precision under a model-wide budget, giving higher-precision priority to tiles important to either phase.
Packing stores one selected representation per tile, preserving 4-bit weights in compact form through storage and loading.
Phase-specialized kernels expand 4-bit weights on-chip to share INT8 computation with 8-bit weights and activations, directly consuming the same packed model.

 
 Across Llama-3.2-3B, Qwen3-4B, Ministral-3-8B, and Qwen3-14B, AlignQuant achieves maximum 2.50 × 2.50\times inference speedups over BF16 on an NVIDIA A100, NVIDIA H100 NVL, and RTX 4090 GPUs while preserving model quality.
These results show how preserving precision granularity through weight storage and computation translates local quantization choices into practical inference efficiency.
Our contributions are as follows:

 
 1. 
 
 Tile-Aligned Precision Design: 
We develop a two-dimensional weight-tile organization that permits local bit-width choices within output channels.
The same partition defines the regions evaluated during calibration and the units used for compact storage and GPU loading.

 2. 
 
 Joint Prefill/Decode Allocation: 
We develop a loss-aware rule that scores local projection-output changes from 8-to-4-bit substitutions under 8-bit activations.
Joint prefill/decode calibration produces one precision map under a model-wide storage budget, prioritizing 8-bit retention for tiles important to either phase.

 3. 
 
 Compact Storage and Direct Execution: 
We develop prefill- and decode-specialized integer kernels that directly consume a compact model with one selected representation per tile.
Compact 4-bit weight loads and on-chip expansion let both weight formats share INT8 arithmetic for efficient inference.

 

 
 2 Related Work

 
 Mixed-precision LLM quantization couples three design dimensions: the granularity at which precision varies, the representation used to realize heterogeneous precision, and the numerical transformations used to reduce quantization error.

 
 Sensitivity-aware precision allocation has progressively moved from coarse model structure toward localized decisions.
Layer-wise methods reduce the number of precision decisions and preserve regular operators, while coupling regions of different sensitivity to one bit-width across each layer
 ( Lee et al., 2025 ; Zhao et al., 2025 ) .
Channel-, output-feature-, and group-wise methods capture finer heterogeneity through structured units, coupling the weights within each unit to one precision and, under layer-local budgets, constraining high-precision placement
 ( Chen et al., 2024 ; Huang et al., 2024 ; Zheng et al., 2026 ; Harma et al., 2026 ) .
Block-level schemes expose more local choices through hardware-aligned partitions, using global budgets, Fisher-weighted perturbation, or outlier-aware clustering for bit-width selection
 ( Li et al., 2026 ; Nie et al., 2026 ; Hooper et al., 2025 ; Xie et al., 2025 ) .
Per-weight salience aggregation captures additive contributions, while whole-block precision changes interact through the projection output
 ( Nie et al., 2026 ; Hooper et al., 2025 ) .
Phase-adaptive methods vary precision across inference phases and generation steps, adding runtime selection among quantized weight representations
 ( Chen et al., 2025 ) .
Allocation therefore depends on spatial granularity, sensitivity evidence, and precision sharing across inference phases.

 
 Low-bit representation and execution approach the same trade-off from the systems side.
Low-bit systems co-design numerical formats, packing, data movement, and kernels for efficient GPU computation
 ( Dettmers et al., 2022 ; Zhao et al., 2024 ; Lin et al., 2025 ; Hu et al., 2025a ) .
Within this category, uniform weight formats couple sensitive and less sensitive regions to the same bit-width
 ( Lin et al., 2025 ; Hu et al., 2025a ) .
Executable mixed-precision systems organize heterogeneous weights through output-feature partitions, reordered blocks, expert groups, or hardware-supported formats, tying their precision choices to corresponding layouts, indexing, or arithmetic paths
 ( Zheng et al., 2026 ; Nie et al., 2026 ; Duanmu et al., 2025 ; Liu et al., 2026 ; Jang and Tambe, 2025 ) .
Representation-centric methods use sparse outliers, residual subspaces, reusable binary codes, or fractional-bit quantizers to improve fidelity or precision flexibility, with corresponding indexed accesses, auxiliary products, or specialized reconstruction
 ( Dettmers et al., 2023 ; Saxena et al., 2024 ; Park et al., 2026 ; Lee and Song, 2026 ) .
Inference efficiency therefore depends on how compact representations map to actual GPU arithmetic.

 
 Transformation-based quantization reshapes weight and activation distributions to reduce quantization error.
Scaling methods protect salient weights or redistribute quantization difficulty between weights and activations, with flexibility limited to feature-wise rescaling
 ( Xiao et al., 2023 ; Lin et al., 2024b ) .
Rotation- and permutation-based methods redistribute outliers across feature dimensions, while transforms spanning precision partitions change the weights assigned to each quantized region
 ( Ashkboos et al., 2024 ; Liu et al., 2025 ; Lin et al., 2024a ) .
Affine and jointly optimized scaling and orthogonal transformations offer richer distribution shaping, while spatial bit-width placement remains a separate decision
 ( Ma et al., 2024 ; Hu et al., 2025b ; Sun et al., 2024 ) .
Runtime smoothing adapts channel scales during inference to control dynamic ranges, while loss-sensitive weight placement requires a separate allocation criterion
 ( Yi et al., 2025 ) .
These approaches improve numerical fidelity, while executable mixed precision also requires compatible transformation, allocation, and execution partitions.

 AlignQuant uses a common two-dimensional weight-tile partition to connect precision allocation, compact storage, and GPU execution .
Each tile uses 4-bit or 8-bit weights, while uniform 8-bit activations provide a common input format for hardware-accelerated INT8 computation.
Offline calibration produces a precision map under a model-wide weight-storage budget.
This map records the selected bit-width at each tile coordinate and determines the weights stored in one packed model shared by prefill and decode.

We evaluate each replacement of 8-bit weights with 4-bit weights through its local projection-output change, weighted by gradients of the full model loss.
Prefill and decode provide separate calibration evidence, which is combined to select one representation per tile.
The runtime uses the selected weights and scales with execution schedules adapted to the two phases.

 
 3.1 Tile-Level Precision Assignment

 
 We introduce offline precision allocation to select 8-to-4-bit replacements with the smallest estimated impact under a storage budget .
The allocation leverages per-tile 4-bit and 8-bit candidates, multi-phase activation and gradient evidence, and a target 4-bit fraction.

 
 For a linear projection Y = X ​ W ⊤ Y=XW^{\top} , let X ∈ ℝ M × K X\in\mathbb{R}^{M\times K} be the input activations and W ∈ ℝ N × K W\in\mathbb{R}^{N\times K} the weights, where M M is the number of activation rows and K , N K,N are the input and output dimensions. Each row of W W corresponds to an output feature and each column to an input feature. We partition all quantized weight matrices into equal-sized two-dimensional tiles, with model-wide set 𝒯 \mathcal{T} . Each t ∈ 𝒯 t\in\mathcal{T} is identified by its layer, projection, and matrix position, allowing different regions within an output channel to use different bit-widths .

 
 Let ρ ∈ [ 0 , 1 ] \rho\in[0,1] denote the target fraction of 4-bit tiles. Since all tiles contain the same number of weights, each 8-to-4-bit replacement saves the same storage. Thus, the budget determines how many tiles use 4-bit weights, while the scores determine which ones .

 
 Quantized candidates. 
As shown in Figure  2 (1), candidate construction applies orthogonal input and output transformations ( V V along K K , U U along N N ) to redistribute outliers and minimize quantization error ( Ashkboos et al., 2024 ; Liu et al., 2025 ) , yielding symmetric 4-bit and 8-bit candidates per tile.
Aligning groups with tile boundaries keeps each transformed weight tile ( W ~ = U ​ W ​ V \widetilde{W}=UWV , X ~ = X ​ V \widetilde{X}=XV ) within its assigned precision region.
The paired output reconstruction preserves the floating-point projection (Appendix  B.1 ).

 
 Let W ^ 4 , t \widehat{W}_{4,t} and W ^ 8 , t \widehat{W}_{8,t} denote the reconstructed 4-bit and 8-bit candidates of the same transformed tile.
Multiplying the values by their own scale puts both candidates in the same numerical coordinates for comparison .
The precision assignment selects the integer values and scale retained for inference.
Calibration and inference use the same 8-bit activation quantizer, so candidate comparisons reflect deployed inputs (Appendices  B.2 and  F.1 ).

 
 Output perturbation from precision reduction. 
Joint scoring in panel (2) of Figure  2 begins by measuring the local projection-output change caused by replacing tile t t ’s 8-bit candidate with its 4-bit candidate.
This change depends on both the candidate weight difference and the activations multiplied by it.

 3.2 Compact Mixed-Precision Representation

 
 In panel (3) of Figure  2 , packing stores one selected integer representation per tile together with its FP32 reconstruction scale.
Each byte stores two signed 4-bit values or one signed 8-bit value, so a 4-bit tile uses half the integer-weight storage of an equally sized 8-bit tile.
The selected scale accompanies those values through storage and computation.

 
 Selected 4-bit and 8-bit tiles occupy separate contiguous buffers.
A one-bit precision label selects the buffer for each logical tile.
Within that buffer, the row offset marks the start of its output-tile row, and the count of preceding same-precision tiles determines its position.
This mapping lets the runtime locate the selected weights and scale from the original tile coordinate .
Indexing rules, bit ordering, and kernel layouts are detailed in Appendix  E.1 .

 
 With a target fraction ρ \rho of 4-bit tiles, nominal integer-weight storage is 4 ​ ρ + 8 ​ ( 1 − ρ ) = 8 − 4 ​ ρ 4\rho+8(1-\rho)=8-4\rho bits per quantized weight; the realized value uses the rounded tile count.
Complete packed storage also includes reconstruction scales and indexing metadata.
Appendices  E.2 and  G.7 give storage accounting and memory-measurement details.

 
 3.3 Direct Prefill/Decode Execution

 
 The execution stage prepares the selected weights for GPU integer computation (Figure  2 , panel (4)).
Both weight formats use a common INT8 path, with schedules that exploit weight reuse in prefill and parallel dot products in decode.

 
 Integer operand preparation. 
The runtime first applies the input-side transform V V and quantizes the activations to 8 bits using the same numerical procedure as calibration.
In the direct mixed-tile kernels, 4-bit values stay packed during GPU-memory loading and expand on chip into signed INT8 operands.
Sign extension preserves each selected integer value, and the stored scale preserves the reconstructed value of the 4-bit candidate.
8-bit weights provide signed INT8 operands directly.

 
 Prefill weight reuse. 
Prefill processes multiple activation rows, so its Tensor Core INT8 schedule reuses each weight tile across their output computations.
Short-prefill kernels prepare mixed-tile operands on chip.
For long-prefill projections containing both formats, the runtime expands the selected weights into a temporary INT8 buffer in GPU memory once per projection call.
The Tensor Core schedule reuses the prepared weights across activation-row groups , reducing the conversion cost per group while preserving each tile’s values and scale.

 
 Decode parallelism. 
Single-sequence decode has one activation row ( M = 1 M=1 ), giving a matrix-vector workload.
The kernel directly loads the packed weight tiles and forms INT8 operands on chip.
DP4A accumulates four products of signed 8-bit operands per instruction into an INT32 result.
Work is distributed across output features and input-column groups , allowing multiple GPU threads to contribute to each output in parallel.
Their partial dot products are combined, drawing parallelism from both weight-matrix dimensions.

 
 Output reconstruction. 
For both schedules, each tile product first accumulates in INT32.
The corresponding activation and weight scales restore its contribution before FP32 accumulation across input tiles.
This per-tile rescaling combines contributions from both weight precisions in the same numerical coordinates .
Split-reduction schedules combine their FP32 partials in a fixed order, after which the output-side transform U U restores the projection output.
The phase transition reuses the same precision map and selected weights.

 
 Shared activation preparation. 
Projections with matching inputs and transforms (e.g., Q/K/V or gate/up) share input preparation.
Each group transforms and quantizes its input once , reusing 8-bit activations across projections while retaining independent weights, scales, and output transforms (Appendices  E.3 and  E.4 ).

 
 Together, these designs preserve local precision flexibility while making each 4-bit choice reduce stored weight bytes.
Joint calibration and phase-specific weight preparation support efficient deployment and generation with one compact model.

 4 Experiments

 
 4.1 Experimental Setup

 
 We evaluate whether AlignQuant improves inference efficiency while preserving model quality, with allocation controls examining the value of local precision placement.
The main text focuses on Llama-3.2-3B-Instruct; Appendix  H extends the evaluation to Qwen3-4B-Instruct-2507, Ministral-3-8B-Instruct-2512-BF16, and Qwen3-14B.

 
 Datasets and Metrics. 
We evaluate language modeling via WikiText-2 perplexity and reasoning/understanding via HellaSwag, MMLU, ARC-Challenge, LAMBADA, PIQA, and WinoGrande.
Long-context capabilities are assessed using LV-Eval QA (16K–64K length levels) and LongEval line-retrieval exact-match accuracy.

 
 Configuration and Comparisons. 
The default model uses 64 × 64 64\times 64 tiles, 60% 4-bit weights, and 8-bit activations.
BF16 is the original-model reference; uniform 4-bit weights provide the low-bit reference.
Structural and random controls test placement (Appendix  G.1 ), alongside GPTQ, AWQ, MixLLM, and SFMP ( Frantar et al., 2022 ; Lin et al., 2024b ; Zheng et al., 2026 ; Nie et al., 2026 ) .

 
 Hardware and Measurement. 
Primary measurements use an NVIDIA A100-SXM4 40 GB GPU, with additional Llama-3.2-3B tests on H100 NVL and RTX 4090.
We report time to first token (TTFT), time per output token (TPOT), throughput, memory, and energy over the full inference path (Appendix  G ).

 
 4.2 Inference Efficiency

 
 BF16 retains the original optimized model; Hugging Face FP16, shown as Torch FP16, provides the FP16 reference used in prior quantization evaluations ( Lin et al., 2024b ) .
On Llama-3.2-3B, AlignQuant reaches 132.28 tokens/s, 2.27 × 2.27\times BF16 and 2.75 × 2.75\times GPTQ throughput , while reducing resident memory from 5.99 to 2.72 GiB and achieving the lowest energy in Table  1 .
The compact selected representation therefore converts low-bit projection efficiency into complete-model generation gains.

 
 Varying request shape shows how the benefit changes with the balance between prompt processing and generation.
 AlignQuant leads the displayed throughput comparisons in Figures  1 and  5 .
For long prompts, longer continuations amplify the gain over BF16 : repeated token generation gives the packed-load decode path a larger share of the request.
The same selected model therefore supports different request shapes while its execution schedules exploit their available reuse and parallelism.
Additional system results and runtime ablations appear in Appendices  H.4 and  H.5 .

 4.4 Long-Context Evaluation

 
 Beyond general benchmarks, we evaluate long-context information retrieval and reasoning at LV-Eval’s 16K, 32K, and 64K length levels.
Using the dataset indices in Table  3 : 1 cmrc_mixup (Chinese reading comprehension); 2 dureader_mixup (Chinese QA); 3 hotpotwikiqa_mixup (multi-hop Wikipedia evidence retrieval); 4 lic_mixup (long-input comprehension and localization); 5 – 7 loogle_CR/MIR/SD_mixup (comprehension/reasoning, multiple-information retrieval, and short-dependency QA); and 8 – 9 multifieldqa_en/zh_mixup (English and Chinese multi-field retrieval).

 
 LooGLE-SD ( 7 ) shows how selective precision behaves as context grows (Table  3 ).
At the 64K level, AlignQuant scores 48.06 alongside BF16’s 48.81, versus 47.24 for MixLLM and 41.69 for AWQ.
Its margin over AWQ grows from 2.35 to 6.37 points, showing that precision retained in sensitive regions remains useful at longer contexts .

 
 Allocation at long contexts. 
Comprehension and reasoning further distinguish precision placement: at the 64K level, AlignQuant scores 24.81 on LooGLE-CR ( 5 ), versus 22.42 for reduction-column and 20.57 for output-row allocation.
This supports local precision choices within output channels (Appendix  H.2 ).

 
 Retrieval across input lengths. 
LongEval resolves length effects across 39 settings from 2.7K to 51.0K tokens (Figure  6 ).
Short inputs are similar, while longer inputs separate the methods: at the longest input, AlignQuant matches BF16 at 48%, versus 40% for MixLLM and 31% for AWQ, preserving successful retrieval at the demanding end of the sweep.

 
 Retrieval allocation controls. 
At the longest inputs, AlignQuant achieves 48% accuracy, outperforming structured (33%–39%) and random (25%) placements. This demonstrates the value of preserving precision within targeted weight regions to retain information as context grows.

 
 Across these evaluations, AlignQuant combines quality preservation and faster generation in one compact model .
Loss-aware tile scoring identifies the weight regions worth protecting, while tile-aligned storage and integer execution make those selected weights efficient to use.
The common tile structure connects these numerical and computational choices throughout deployment.

 
 5 Conclusion

 
 AlignQuant demonstrates that fine-grained precision choices can coexist with regular GPU computation when the precision unit supports both sensitivity evaluation and efficient execution.
Our results show this preserves quality while boosting inference efficiency, suggesting a broader principle for future quantizers: design precision units for compact storage and regular execution, then allocate bits based on local output sensitivity.

 Appendix F Design Rationale

 
 F.1 Activation Precision

 
 One A8 input group contributes to several output tiles, each of which can independently select W4 or W8.
Using the same reconstructed input makes the candidate comparison specific to the weight substitution and lets compatible projections share activation preparation.
A8 also supplies the operand width used by both Tensor Core INT8 multiplication and DP4A ( Xiao et al., 2023 ; Lin et al., 2025 ) .

 
 For a fixed represented range, A8 provides 256 integer levels and A4 provides 16.
An A4 variant would recalibrate the candidate scores using its reconstructed inputs and prepare those values for the chosen arithmetic.
Mixed activation precision would add format choices for input groups and coordinate them across their consuming projections.
Uniform A8 keeps the input representation shared while the weight allocation follows local sensitivity.

 
 F.2 Precision Granularity and Execution

 
 The weight tile determines which values share a precision choice, while activation groups and thread blocks determine how those values are used.
A 64 × 64 64\times 64 weight tile can therefore support a single decode row or multiple prefill rows.
Smaller weight tiles provide more allocation choices and increase scale and label storage, whose contribution is approximately 33 / ( b N ​ b K ) 33/(b_{N}b_{K}) bits per weight before row offsets and byte alignment.

 
 Joint calibration assigns the shared weights using evidence from both phases.
At runtime, direct loading forms INT8 operands on chip, while long prefill reuses prepared operands across many rows.
These schedules preserve the selected values and scales while adapting their preparation to the available reuse.

 Appendix H Additional Results and Analysis

 
 H.1 General Quality Results

 
 To examine whether the quality preservation extends across model families and sizes, we repeat language modeling and downstream evaluation on Qwen3-4B, Ministral-3-8B, and Qwen3-14B.
Tables  6 , 10 , and  8 show a recurring pattern: selective W8 retention improves the reported task scores over W4A8 while preserving the predictive behavior of the original model.
For Qwen3-4B, LAMBADA accuracy reaches 63.38%, alongside 63.40% for BF16 and 58.14% for W4A8.
For Qwen3-14B, HellaSwag accuracy is 78.77% alongside 78.83% for BF16, and WikiText-2 perplexity is 10.94 alongside 10.78.
The preservation therefore appears in both correct-answer prediction and the probabilities assigned to text.

 
 This behavior is consistent with the numerical object evaluated during allocation.
As detailed in Appendices  D.1 and  D.2 , each score measures the output change caused by replacing a reconstructed W8 candidate with its W4 candidate under the observed A8 inputs.
The loss-gradient weighting connects that local change to the model’s prediction objective.
Each model supplies its own candidate differences, activations, and gradients, so the same procedure can assign W8 to different regions under a common storage budget.
The downstream results support these selected regions as useful locations for retaining additional numerical resolution.

 
 Allocation controls. 
The matched-budget controls examine how much of this quality depends on the spatial freedom of the allocation.
On Qwen3-4B, AlignQuant achieves 13.15 perplexity, compared with 13.32 to 13.88 for the structured and random placements (Table  7 ).
On Qwen3-14B, LAMBADA accuracy reaches 69.65%, compared with 67.55% to 67.79% for the structured controls and 66.45% for random placement (Table  9 ).
These comparisons hold the W4 fraction fixed, so the improved predictions reflect a more effective placement of the available W8 tiles.
The model-wide selection in Appendix  D.4 permits this capacity to follow the tile scores across projections.
Together, these results support retaining local choices in model-wide allocation.

 H.2 LV-Eval Task Results

 
 The additional LV-Eval experiments examine whether the shared precision maps preserve information use as context length increases across different models.
Qwen3-4B maintains a nearly level CMRC trajectory, scoring 24.95, 25.30, and 24.74 at 16K, 32K, and 64K, with the final value matching BF16 (Table  11 ).
Ministral-3-8B preserves a different length response on LooGLE-SD: its score changes from 59.44 at 16K to 56.18 at 64K, alongside the BF16 change from 58.47 to 55.09 (Table  12 ).
Preservation here follows each model’s task-specific trajectory across lengths.
The selected representation retains the first example’s nearly level response and the second’s gradual change.

 
 Qwen3-14B shows a stronger dependence on selective precision at the largest context length (Table  13 ).
On LooGLE-SD, AlignQuant scores 21.51, 18.96, and 17.86 from 16K to 64K, while W4A8 scores 18.54, 15.58, and 8.55.
A related pattern appears in English multi-field question answering ( 8 ), where the 64K score is 14.28 with AlignQuant , 14.66 with BF16, and 5.89 with W4A8.
The separation across these tasks shows that the value of higher precision extends to several forms of long-input information use.
The retained W8 regions help preserve the model’s ability to extract and use relevant evidence at lengths where the precision choice has a larger effect on the answer.

 
 Allocation controls. 
The fixed-budget comparisons further distinguish the effect of precision placement.
For Qwen3-14B on LooGLE-SD, the strongest structured control changes from 21.03 at 16K to 10.11 at 64K, compared with 21.51 and 17.86 for AlignQuant .
For Ministral-3-8B on LooGLE-CR at 64K, AlignQuant scores 26.77 versus 21.45 to 23.37 for the structured and random allocations.
The available W8 capacity is the same, yet the locally selected map preserves more contextual information in both cases.

 
 The shared-map design connects these results to the calibration procedure in Appendices  C.2 and  D.3 .
Prefill and decode contribute their own activation and gradient observations, and their normalized scores determine one selected representation per tile.
That representation is reused across the evaluated context lengths.
The task trajectories show that the resulting choices continue to protect useful predictions as the amount of input context changes.

 The perturbation construction explains how these regions receive distinct scores.

Changing the W4 fraction changes which numerical values are stored and how many bytes they occupy, while the arithmetic organization remains shared.

 
 This distinction explains how the allocation and execution components fit together.
The budget and sensitivity ranking determine the selected numerical model.
Packing realizes that choice in bytes, and operand preparation presents those same selected values to the integer kernels.
The sweep shows how one execution design supports several compact storage levels.

 The cross-model system experiment tests whether the quality-preserving allocations also deliver efficient generation as model dimensions and parameter counts change.
All four models use one A100 GPU with batch size 1, a 128-token prompt, and 512 generated tokens.
Table  20 shows lower TPOT and higher throughput for AlignQuant on every model, with TPOT speedups of 1.53 × 1.53\times to 2.50 × 2.50\times over BF16.
On Qwen3-14B, TPOT decreases from 30.29 to 19.85 ms, and energy per 1,000 generated tokens decreases from 6972.05 to 4354.57 J.
The largest model therefore combines the task-quality preservation reported earlier with lower time and energy costs for generation.

 
 The common tile representation provides the connection across these model sizes.
Each projection stores its own selected values and scales, while the execution organization in Appendix  E.3 distributes work over output tiles and input-column groups.
This lets the allocation follow each model’s sensitivity distribution while reusing the same forms of integer computation.
The cross-model measurements show that this combination remains effective across the evaluated projection geometries.
Quality and efficiency are thus two properties of the same selected models.

 
 To examine whether the execution design carries across GPUs, we repeat the Llama-3.2-3B workload on H100 NVL and RTX 4090.
 AlignQuant achieves the highest throughput and lowest TPOT among the compared configurations on both devices (Tables  19 and  18 ).
Throughput reaches 167.49 tokens/s on H100 NVL and 180.64 tokens/s on RTX 4090, compared with their respective BF16 results of 81.54 and 108.05 tokens/s.
Both measurements also report lower energy per generated token and a resident footprint of approximately 2.7 GiB.

 
 The representation and operand preparation have complementary roles in these results.
The selected W4 values provide compact storage, and their expansion preserves the integer values and reconstruction scales used by the common INT8 arithmetic.
The same numerical representation can therefore be used by the phase-specific kernels on each evaluated platform.
The measurements support carrying the local precision choices into efficient execution across these devices.

 
 Persistent weight storage gives the model’s base footprint, while longer requests add activations, key/value states, and temporary execution buffers.
We therefore measure peak GPU allocation across prompt lengths to assess the representation within a complete workload.
From 128 to 16K prompt tokens, AlignQuant ’s peak increases from 2.72 to 4.44 GiB, while BF16 increases from 6.09 to 8.88 GiB (Table  21 ).
At 16K, AlignQuant uses half the BF16 peak memory and records the lowest peak among the compared configurations.
The compact model thus retains a substantial memory benefit as context-dependent state grows.

 
 The distinction between persistent and temporary storage is specified in Appendices  E.2 and  E.3 .
For long prefill, a projection prepares selected weights in a temporary INT8 buffer for reuse across activation-row groups.
The packed model remains the persistent representation, and the prepared operands belong to the current projection call.
Peak-memory measurement includes these workload-dependent lifetimes alongside the model and context state.
The observed footprint therefore evaluates compact storage together with the execution strategy that uses it.

The CUDA Graph control measures a change in execution submission within AlignQuant , while the BF16 comparison evaluates the complete deployed method .
Each runtime effect is conditional on the other components active in its comparison.
Adaptive decode splitting lowers TPOT from 8.54 to 7.54 ms, while TTFT remains approximately 19.6 ms in both configurations (Table  22 ).
The change is concentrated in the generation schedule.
As described in Appendix  E.3 , single-sequence decode has one activation row, so the kernel exposes additional parallel work through output features and input-column groups.

The implementation in Appendix  E.4 prepares a common transformed 8-bit input for compatible query/key/value or gate/up projections.
Each consumer then uses its own selected weights, scales, and output transform.
The reductions in both metrics match this placement of the optimization: input preparation is reused across projections during both prompt processing and generation.
The selected precision map stays attached to each projection while common input work is shared.

 
 CUDA Graph execution addresses the submission of the repeated inference computation.
Compared with individual kernel launches, it lowers TPOT from 21.07 to 7.54 ms and increases throughput from 47.45 to 132.28 tokens/s (Table  22 ).
Peak GPU memory is 2.73 and 2.72 GiB, respectively, so the timing change occurs at a similar runtime footprint.
The comparison holds the selected numerical model fixed and changes how its computation is submitted.
It shows that efficient submission is an important part of converting fast low-bit projection work into full-model generation speed.

 
 The controls identify improvements at three levels: reduction scheduling within a projection, input reuse across projections, and submission of repeated model computation.
These execution choices operate on the values selected by the same calibration and packing procedure.
Combined with the quality ablations, the results explain the roles of the design: local sensitivity guides where numerical precision is retained, compact packing realizes those choices in memory, and the runtime organizes their computation efficiently.
The shared tile partition connects these roles in one deployed model.
