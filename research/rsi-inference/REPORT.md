## 0　结论速览

全文论证在 [paper/PAPER.md](./paper/PAPER.md)。四条结论各自对应的主张：

1. 只有 kernel 层的循环真正闭合，因为只有这一层的正确性与性能判据都能被程序廉价判定[c-object-kernel][c-object-serving]。
2. 反馈强度是解释改进率的主坐标：同一模型换更严的测量会从 1.43 倍掉到 0.88 倍[c-feedback-ladder]。
3. 增益的数字不可直接比较（1.07x 到 9.29x），代价结构却高度一致（21% 想、79% 跑）[c-gain][c-cost]。
4. 回报曲线先陡后平，且增益主要来自脚手架而非权重，故当前是「有累积性的自动优化」而非 RSI[c-plateau][c-moat]。

另有两条支撑性判断：验证器而非生成器是瓶颈[c-verifier]；kernel 级加速比到端到端之间存在漏斗，甚至反号[c-e2e]。
边界与口径问题见[c-boundary][c-measure]；循环的四种形态见[c-loop-forms]。

## 1　问题

「基于 DeepResearchRSI，调研模型推理优化的 RSI，写成论文。」

这句话里有两个词需要先被钉死，否则整篇会变成空话：

- **推理优化**：不是一件事，而是四层（kernel/算子、图与编译、服务与调度、量化与压缩）。
- **RSI（递归自我改进）**：不是一种方法，而是四种工程形态（单轮+验证、多轮反思、RL、脚手架自演化）。

故本档案的第一个动作不是检索，而是给这两个词各写一条判据（见 `brief.yaml` 的
`core_claim_to_test`）。核心假设：

> 改进率由**反馈信号的信噪比**决定，而不是由模型能力决定。

这条假设可被反驳：找到「反馈极弱但改进率高」或「反馈极强但改进率低」的公开案例即失效。
第 7 章的四种失效情形是它的边界。

## 3　逐轮记录

### r1　检索式设计：为什么不能只搜 "RSI"

第一次尝试用 `all:"recursive self-improvement"` 单独检索，召回的大多是通用 agent
自演化论文，与推理栈无关。改为五组式子后（kernel / system / self-improve / RL / evolve），
26 条式子共命中 1853 条、去重 1594 篇，其中 2026 年 1388 篇——这个分布本身说明
该方向在过去 12 个月才真正成型。

**教训**：主题不在 arXiv 的分类体系里时，检索式必须按「圈子」分组，
而不是按关键词的同义词扩展。

### r2　粗筛：把 1594 篇压到 160 条可读标题

`screen_rsi.py` 用三维打分（对象 / 循环 / 自主），并对同形异义做硬排除
（遥感影像、重复性劳损、推荐系统……）。排除命中 58 篇——「RSI」在别的领域
确实是个常用缩写，这一步不做，后面全是噪声。

**教训**：缩写型主题的第一步必须是同形异义排除，且要写成代码而不是靠人眼。

### r3　纳入集：45 core + 12 旁证

按「在论证里占哪个位置」划分：core 实现循环，adjacent 提供判据的一半
（性能上限、验证方法、失败模式）。同一个位置有第三篇时取证据更硬的那篇——
因为本文的论点是判据，不是文献普查。

**这里的取舍是主观的，且没有被校验器覆盖。** 记录在此以便复核。

### r4　全文抓取：43/45

两篇没有 HTML 全文（arXiv 只对较新论文生成 HTML）。这两篇的证据只用摘要快照，
locator 标 `abstract` 而非 `fulltext#...`，让「这条证据有多硬」可被程序区分。

### r5　证据抽取：先机筛，再人判

第一版直接让模型读全文找句子，读了三篇就发现不可行：全文平均 6 万字符，
注意力会漂移，最后记住的仍是摘要。改为两步：

1. `make_digest.py` 用正则把候选句压到每篇约 20 条（必须含硬数 + 语境信号）；
2. 人工从 digest 里判定哪条进 `evidence.csv`。

**这一步是本档案质量的关键**：digest 有 532 行、约 9.5 万字符，是原文 270 万字符的 3.5%。

### r6　E1 校验暴露的三个真缺陷

`build_claims.py` 写完立刻自查「quote 是否是快照原文子串」，抓出三类错误：

1. **手抄差空格**：LaTeXML 的换行位置不可预测，同一句可能被切成三行。
   → 加了 `resolve()`：把模式里的空格当 `\s+` 去原文里找，**返回命中的原文本身**。
   子串性质由构造保证，不再靠人眼核对。
2. **引错了论文**：把 DSL 那篇（2603.29010）的「21%/79% 时间拆分」记成了 SpecGen 的。
   这是最危险的一类错误——数字对、句子对，只有出处错。
3. **大小写/单复数**：`The pipeline produces` 实为小写开头。

**教训**：E1 不只是形式检查。它抓到的第 2 类错误，任何「读起来很顺」的复核都发现不了。

### r7　一次自我否决：删掉「反馈阶梯」那张图

原本设计了一张「反馈强度 vs 改进」的折线图，四个点分别是
1.0 / 0.25 / 1.15 / 2.03。`audit_paper.py` 直接判 FAIL：这四个数在对应主张的
证据里找不到——它们是从不同论文里各取一个数**拼**出来的。

按本仓库的规矩（P2：数值可回溯），拼出来的横截面不构成证据。故：

- 删掉该图与该数据集；
- 把「阶梯」改为**方向性论证**，只用「同一系统、只换反馈」的对照实验
  （e-017 / e-020 / e-021 / e-059），每一条都是论文内的消融。

**这是本次调研最重要的一次否决**：图的形状是对的，故事也讲得通，
但它跨越了「可比」这条线。

### r8　补充证据：把每条主张补到 4 条以上

首轮 9 条主张里，`c-feedback-ladder` 有 7 条证据但集中在 4 篇论文上。
补了 e-059（SOL 引导）与 e-073..e-076 的探针核对后，
把分级依据改为「每一级都有同一系统内的对照」。

新增三条主张：`c-e2e`（端到端漏斗）、`c-moat`（脚手架而非权重）、
`c-plateau`（回报曲线先陡后平）。这三条是写作过程中**先有反例、后有主张**，
不是先有框架再找证据。

### r9　论文层：图与数的对齐

`audit_paper.py` 又抓出两处：

- `1.72` 在 `c-gain` 的全部证据里找不到（因为它在 `c-plateau` 的 e-032 里）；
  → 补 e-078（AdaExplore 摘要同时给了 L2 与 L3）。
- `0.25` / `2.03` 来自已删除的阶梯图，一并消失。

最终：4 张图、6 张表、20 个数值全部回溯成功。

### r10　LaTeX 排版：四处真问题

逐条记下来，因为它们都不是「调参」，而是判据与文档约定对不上。

1. **图号与表号必须按「出现顺序」编号。** 初版按话题顺序写（图 1 增益、图 2 阶梯、
   图 3 预算、图 4 漏斗、图 5 成本），但正文里成本图排在预算图之前，
   `check_paper.py` 的 I3 直接判「图编号不连续：[1,2,2,4]」。
   改成按出现顺序重编后通过。**图号是版面事实，不是写作计划。**
2. **表格题注也必须按出现顺序。** 同一条规则，表 1（协议对照）出现在第 2 页、
   表 2（四层对象）在第 4 页、表 4（七条增益）在第 5 页——原本把「七条增益」
   写成表 3，于是表 3 出现在表 4 之后。I3 报错位置精确到页码，改起来很快。
3. **图片 alt 文本里的长描述会把图注撑成两段。** `![图 N　描述](path)` 的写法
   在 `md_to_tex.py` 里只取路径、不取 alt；但 `check_paper.py` 的 I3 用
   `!\[图 (\d+)\]` 匹配，alt 里带全角描述就匹配不到 → 「图引用 [] 与图标题不匹配」。
   改为 `![图 N](path)` + 单独的题注行（描述并入题注）。
4. **参考文献不能按论文标题全列。** 40 条完整标题把参考文献挤到第三页，
   末页只剩英文条目；`check_latex.py` 的 X1 按 CJK 字数计，英文条目不计数，
   于是报「p9=53 字」。改为 `\scriptsize` + 标题截断到 40 字符 + 编号右对齐，
   回到 9 页。

另有一条 WARN 保留未修：L6 行宽填充率 90.1%（阈值 95%）。原因不是排版错，
而是本文字数按「每行排到接近版心」统计时，双栏里 `figure*`/`table*` 跨栏
浮动体前后的短段被当成同段非末行，拉低了中位数。`pd-disagg` 与
`cuda-kernel-gen` 在同一个检查下分别是 53.4% 与 53.4%（均为 FAIL），
本文 90.1% 已是三篇里最高的。**这是一个已知的度量口径问题，不是本文的排版缺陷**，
故按 WARN 保留，并在 `paper/latex/main.tex` 里标注。

## 4　已知缺口

1. **发布偏差**：负结果很少被写成论文。第 7 章的四种失效，多数是从正面论文的
   消融与附录反推的，不是来自专门的负面研究。
2. **摘要级证据的占比**：45 篇 core 里 43 篇有全文，但有些关键数字只在摘要里
   （例如 ForgeKernel 的 +10%）。这类证据的 locator 标 `abstract`。
3. **纳入集的主观性**：r3 的取舍没有被校验器覆盖。
4. **无自建实验**：本文没有跑任何 kernel。所有数字都是二手，但每条都能点回原文。

## 5　未解决问题

- 「反馈强度」这条轴目前只有**方向性**证据（多组同向消融），没有**定量模型**。
  要把它变成可预测的公式，需要在同一硬件、同一基线上做一次受控实验：
  固定模型与预算，只切换 L1–L4 四级反馈。本文没有条件做，故只提出轴，不提出公式。
- 服务层的闭环证据比 kernel 层稀薄一个量级。本文因此把它写成「半闭合」，
  而不是给出与 kernel 层对称的结论。
